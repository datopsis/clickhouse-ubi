# Security policy

## Supported versions

Security fixes are applied to the latest published image line. Older ClickHouse or UBI combinations may be rebuilt when practical, but are not supported unless explicitly documented in a release.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's **Security** tab and select **Report a vulnerability** to submit a private security advisory.

Include the affected image tag or digest, architecture, scanner output or reproduction steps, and whether the issue appears to originate in this packaging, ClickHouse, or UBI.

Upstream vulnerabilities should also be reported under the applicable upstream policy:

- ClickHouse: <https://github.com/ClickHouse/ClickHouse/security/policy>
- Red Hat: <https://access.redhat.com/security/team/contact>

## Image verification

Tagged releases are scanned before publication and signed keylessly with Cosign after publication. They include an SBOM and build-provenance attestation generated by BuildKit. Production deployments should use verified image digests.

Scanner results require context. Red Hat often backports security fixes without changing an upstream version string; consult Red Hat's vulnerability data before treating a version-only scanner result as authoritative.

## UBI-installable fix gate

CI and release admission block fixable High/Critical findings from Trivy and
Grype. For positively identified Red Hat RPMs only, admission queries fresh
metadata inside the digest-pinned UBI Minimal builder used by the RPM lock
resolver, with the same enabled repository files and target architecture
(including noarch). The shared loader rejects missing, empty, or unexpected
repositories and disables DNF's skip-if-unavailable behavior. The final image
installs that lock offline; it does not enable additional repositories.

An RPM finding blocks when UBI publishes a candidate at or above any vendor
fixed version, using librpm epoch/version/release comparison. A successful
negative query reports the finding as **deferred**, including the vendor fixed
version, in the job summary and retained JSON. Deferred means still vulnerable,
not remediated. Regenerate the lock with `bash scripts/update-rpm-lock.sh` to
apply installable fixes on both architectures.

Query errors, timeouts, invalid versions, missing repositories, unverified RPM
identity/architecture, and fixable non-RPM findings remain blocking. Unfixed
findings remain visible in complete scanner reports. There are no vulnerability,
package, or date exemptions. Scanner failures and missing reports fail the job.
Both native release architecture scans must pass before signing or release
creation; the existing build publishes the image before these scans.

Scheduled CI checks every six hours. A trusted-main-only tracking job maintains
one issue, commenting only when the deferred set (including vendor fixed
versions and architecture) changes. It closes the issue when that set is empty
and reopens the same issue for new deferrals. Missing or corrupt evidence fails
tracking rather than falsely announcing resolution. PRs never run this job or
receive issue write permission. Raw reports and repository-query evidence remain
available as CI artifacts, including when admission fails.
